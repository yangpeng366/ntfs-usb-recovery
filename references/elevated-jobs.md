# 自动提权作业：本次实战经验

适用场景：当前用户属于管理员组，但日常窗口带 UAC 过滤令牌；磁盘访问和所有权修复需要已授权的管理员令牌。本次复用了管理员预先注册的 Windows 计划任务，日常投递不再弹出新窗口。

## 通道

管理员首次注册固定任务：运行级别 Highest、交互登录令牌、固定解释器及 dispatcher 路径。dispatcher 读取本机队列中的脚本路径，启动作业，写独立输出日志，最后落下包含退出码、时间和任务标识的完成记录。普通窗口只投递并触发已有任务。首次注册的权限要求不能省略。

不要把任意用户可写目录作为高权限脚本来源。队列、dispatcher 和允许执行的作业目录须只对指定管理员账户及 SYSTEM 可写；客户端应校验路径位于允许目录内，并用唯一 job ID 匹配结果。不要把长期任意脚本执行入口开放给其他账户。

## 长作业与中断

- 发起前检查同一通道有无运行中的作业；一通道一次一任务。并行时使用独立队列、输出和完成标记。
- 分离“客户端等待超时”与“作业终止”：超时不表示修复已停。记录任务状态、PID、最后完成项后，再决定等待或续跑，不能直接重投。
- 不凭进程存在断言进度。任务是否完成须同时看退出码、结束记录和用户视角验收；日志无更新时检查进程与系统事件。
- 0xC000013A 表示中断。本次第二轮检查成功后，ACL 扫描中途退出；复验仍有 found.000 拒访，故仅补此项。
- 状态页逐目录写开始、结束、耗时和返回码。大段输出应直接持续写独立日志，避免 Out-String 缓冲到进程结束才见结果。

## 本次通道的实际限制

现有 elev_exec.ps1 只轮询共享 last_run.done，并不能可靠代表子作业退出码；日志头显示 admin=True 也只证明提权成功。2026-11-08 最终修复同时核对独立日志 END、任务退出、普通用户列目录。上文唯一 job ID 和结构化完成记录是后续加固建议，不能声称旧通道已经具备。

icacls 即使只给目录自身授权，本次也出现长时间不返回。停止原任务后先确认任务 Ready 且原进程已退出，再投下一项。最终用备份 DACL 后的 SetFileSecurityW 定点修改完成入口恢复；未宣称后代权限恢复。详见案例。

## 编码与验收

旧 Windows PowerShell 5.1 按系统 ANSI 解析无 BOM 脚本；跨版本执行脚本可保持纯 ASCII。其 Clear-Content 无 Encoding 参数。所有源文件保存 UTF-8 无 BOM，并验前三字节。

提权令牌会掩盖普通用户的访问问题。完成后回到普通窗口，列举所有目标一级目录并抽样下层路径；系统回收目录按原权限保留。本仓保留作业模式与故障证据，部署时须按目标机器账户、目录权限和信任边界配置固定任务。
